01 / WHY METERGATE?

Change the gateway, not your agent workflow

Modern coding agents like Claude Code, Cursor, Windsurf, and OpenClaw run arbitrary tools and consume tokens rapidly. But without a local guardrail, two silent traps emerge: cost blindness (not knowing where tokens were burned) and secret exfiltration (indirect prompt injection reading local .env files and pushing them to external webhooks).

Design Tenet

MeterGate sits silently on 127.0.0.1:8787 or in a --mcp-stdio pipe. It does not phone home to a cloud server, does not require an enterprise login, and does not require complex rewrites of your prompt chains.

• Three-Tier Lightweight Firewall: Front-redacts keys, <3ms local heuristic scoring.
• Official Published Rates: Reconciled line-by-line against actual official provider pricing.
• Zero-Risk Onboarding: Runs in Observe-Only mode as a seamless sidecar.

03 / CONSTRAINTS AS FEATURES

What we didn't build (and why)

Like pi.dev, MeterGate is aggressively minimal. Features other tools bake in are deliberately omitted to preserve your agency, performance, and complete local privacy.

  • No Cloud Telemetry
    We don't collect prompts, bills, or metrics. There are zero background beacons or exfiltration endpoints. Everything lives in your local SQLite file.
  • No Multi-Tenant RBAC Bloat
    MeterGate is explicitly designed as a single-instance local developer gateway (≤32 concurrent in-flight requests with fast-fail HTTP 503). No complex enterprise SSO or user tables.
  • No Heavy Neural Judge Latency
    Tier 2 uses a sub-3ms heuristic concept cluster and N-gram scorer. It adds zero noticeable latency to your agent, while honestly disclosing its known blind spots.
  • No Commercial Paywalls
    Pure MIT license. No feature locks, no 402 Payment Required traps, and no trial expiration timers.
  • No Forced Blocking
    Use metergate serve --mode observe to start with 0% false-positive risk. Gather proof first, enforce when ready.
